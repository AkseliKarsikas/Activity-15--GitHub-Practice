## Part A, Plan for Creating and Maintaining the Repo

1. First, I made a public GitHub repo and named it Activity14-MyName.
2. I kept the default `main` branch and then created a `dev` branch, which is where I did all of my edits.
3. I used the Issues tab to list the tasks I needed to do (like making the README and uploading the Activity 14 files).
4. Whenever I worked on something, I made sure to do it on the `dev` branch. I committed changes with short, clear messages.
5. After each task was done, I opened a Pull Request to merge the work into `main`.
6. I also connected my PRs to the Issues (using “Fixes #1” or “Fixes #2”) so the workflow is clean and easy to follow.
7. I organized the repo into folders so it doesn’t get messy.
8. Once everything looked good, I merged the PRs into `main` and checked that the files were in the right place.

## Part B, Plan for Activity 14 Work

1. I created the Activity14.qmd file in RStudio.
2. After finishing the work inside the QMD, I rendered it into a PDF.
3. Both files were uploaded into the `activity14` folder.
4. I made sure the code, visuals, and explanations were clear and reproducible so someone else could run the QMD again.
5. The goal here was just to keep everything organized, readable, and in the right structure so the professor can easily find the work.
